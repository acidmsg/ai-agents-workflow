## Шаг 3. Python-Оркестратор (Task Planner)

Этот скрипт запускается локально. Он принимает вашу бизнес-задачу, использует Google AI Pro для декомпозиции и автоматически формирует очередь атомарных задач в GitHub Issues.

```python
import os
import json
import requests
import google.generativeai as genai
from dotenv import load_dotenv

# Загрузка переменных окружения
load_dotenv()
GITHUB_TOKEN = os.getenv("GITHUB_TOKEN")
GOOGLE_API_KEY = os.getenv("GOOGLE_API_KEY")

REPO_OWNER = "ваш_github_юзернейм"
REPO_NAME = "ваш_репозиторий"

def generate_task_plan(prompt: str) -> list:
    """Генерация плана задач через Google AI Pro."""
    genai.configure(api_key=GOOGLE_API_KEY)

    # Строгий промпт для вывода только JSON
    system_prompt = """
    Break down the user's complex IT task into atomic, strictly sequential sub-tasks.
    Return ONLY a valid JSON array of objects.
    Format: [{"title": "Step 1 name", "body": "Technical details, paths, and commands"}, ...]
    """

    try:
        model = genai.GenerativeModel('gemini-1.5-pro')
        response = model.generate_content(
            f"{system_prompt}\nUser Task: {prompt}",
            generation_config={"response_mime_type": "application/json"}
        )
        plan = json.loads(response.text)
        return plan
    except Exception as e:
        print(f"[ERROR] Ошибка генерации плана: {e}")
        return []

def create_github_issue(title: str, body: str) -> bool:
    """Создание Issue в GitHub для передачи задачи в OpenClaw."""
    url = f"https://api.github.com/repos/{REPO_OWNER}/{REPO_NAME}/issues"
    headers = {
        "Authorization": f"token {GITHUB_TOKEN}",
        "Accept": "application/vnd.github.v3+json"
    }
    payload = {
        "title": f"[AUTO] {title}",
        "body": f"{body}\n\n**Assignee**: OpenClaw",
        "labels": ["automated", "openclaw-task"]
    }

    try:
        res = requests.post(url, headers=headers, json=payload)
        res.raise_for_status()
        print(f"[OK] Issue создана: {title}")
        return True
    except requests.exceptions.RequestException as e:
        print(f"[ERROR] Ошибка создания Issue: {e}")
        return False

def main():
    global_task = input("Введите глобальную задачу для автономных агентов:\n> ")

    print("[INFO] Анализ и декомпозиция задачи...")
    tasks = generate_task_plan(global_task)

    if not tasks:
        print("[ERROR] План пуст. Прерывание выполнения.")
        return

    print(f"[INFO] Сгенерировано {len(tasks)} задач. Отправка в GitHub...")
    for task in tasks:
        # Базовая валидация структуры
        if "title" in task and "body" in task:
            create_github_issue(task["title"], task["body"])

if __name__ == "__main__":
    main()
```

## Обновленная архитектура с n8n и Linear

Понял вас. Отказ от локальных LLM в роли планировщиков — верное решение, так как API-модели (Google Pro, DeepSeek) несравнимо лучше держат контекст сложных задач. Использование локальной RAG-базы (Qdrant + эмбеддинги) в связке с Zoo Code — оптимальный подход для обеспечения глубокого контекста кодовой базы на этапе вашего ручного ревью.

Внедрение n8n и Linear переводит вашу связку из разряда "набор скриптов" в полноценный асинхронный конвейер.

**Главная причина использования этой связки:** Linear предоставляет идеальную структуру (Epics -> Issues) для хранения состояний (State Machine), а n8n выступает в роли событийной шины (Event Bus), избавляя вас от необходимости писать кастомные поллеры и интеграции.

### Распределение ролей

| Компонент                 | Роль в системе            | Обоснование                                                                                                   |
| :------------------------ | :------------------------ | :------------------------------------------------------------------------------------------------------------ |
| **n8n** (Self-hosted VPS) | Оркестратор и Event Bus   | Ловит вебхуки от Linear/GitHub, управляет вызовами API, маршрутизирует задачи между агентами.                 |
| **Linear**                | Трекер задач (Task Queue) | Визуализация очереди, хранение статусов, назначение задач на конкретных агентов.                              |
| **Google AI Pro**         | Глобальный Планировщик    | Вызывается через n8n. Декомпозирует большие задачи (Epics) в Linear на мелкие пошаговые Issues.               |
| **OpenClaw + DeepSeek**   | Автономные воркеры (VPS)  | Выполняют конкретные Issues из Linear. Работают в терминале, пишут рабочий код, создают ветки.                |
| **Hermes** (API)          | Вспомогательный агент     | Интегрируется в n8n для промежуточных задач (суммаризация, быстрый парсинг логов).                            |
| **Zoo Code + Qdrant**     | Среда контроля (Home PC)  | Ваша основная рабочая станция. RAG-поиск по коду для глубокого ревью Pull Requests, сгенерированных агентами. |

## Пайплайн автоматизации (Workflow)

1. **Постановка:** Вы создаете задачу уровня `Epic` (или тикет со специальным тегом) в Linear.
2. **Планирование (n8n + Google AI):** - n8n ловит webhook от Linear о новом Epic.
   - n8n отправляет описание задачи в Google AI Pro с промптом на строгую декомпозицию.
   - n8n получает JSON-массив шагов и через Linear API создает дочерние `Issues`, назначая их на виртуального пользователя (OpenClaw).
3. **Исполнение (VPS):** - OpenClaw запускается по триггеру (webhook или cron). Забирает тикеты в статусе `To Do`.
   - Под капотом использует токены DeepSeek API для написания кода.
   - OpenClaw делает коммит в новую ветку и открывает Pull Request в GitHub.
4. **Синхронизация статусов:** n8n ловит вебхук от GitHub (о создании PR), меняет статус связанной задачи в Linear на `In Review` и прикрепляет ссылку.
5. **Ваш контроль (Home PC):** Вы открываете VS Code. Через Zoo Code и локальную Qdrant-базу проверяете контекст, делаете код-ревью PR.
   - Утвердили -> Merge (n8n закроет тикет в Linear).
   - Отклонили -> Пишете комментарий (n8n вернет задачу в Linear на доработку агенту).

## Техническая реализация: Интеграция OpenClaw и Linear

Чтобы OpenClaw (или ваш кастомный скрипт-обертка для него) мог автономно забирать задачи, потребуется скрипт для взаимодействия с GraphQL API Linear.

**Скрипт-поллер задач (Python)**
Скрипт извлекает задачи, назначенные на агента, чтобы передать их в OpenClaw.

```python
import os
import requests
from dotenv import load_dotenv

# Загрузка конфигурации
load_dotenv()
LINEAR_API_KEY = os.getenv("LINEAR_API_KEY")
OPENCLAW_USER_ID = os.getenv("LINEAR_OPENCLAW_USER_ID") # ID виртуального юзера-агента в Linear

# GraphQL запрос: получить задачи To Do для конкретного агента
GRAPHQL_QUERY = """
query GetPendingTasks($assigneeId: String!) {
  issues(filter: {
    assignee: { id: { eq: $assigneeId } },
    state: { name: { eq: "Todo" } }
  }) {
    nodes {
      id
      identifier
      title
      description
      branchName
    }
  }
}
"""

def fetch_linear_tasks() -> list:
    """Fetch pending tasks assigned to OpenClaw from Linear API."""
    url = "https://api.linear.app/graphql"
    headers = {
        "Authorization": LINEAR_API_KEY,
        "Content-Type": "application/json"
    }
    payload = {
        "query": GRAPHQL_QUERY,
        "variables": {"assigneeId": OPENCLAW_USER_ID}
    }

    try:
        response = requests.post(url, headers=headers, json=payload, timeout=10)
        response.raise_for_status()
        data = response.json()

        issues = data.get("data", {}).get("issues", {}).get("nodes", [])
        return issues
    except requests.exceptions.RequestException as e:
        # Главная причина проблемы
        print(f"[ERROR] Ошибка сети при обращении к Linear API.")
        # Детали проблемы
        print(f"[DEBUG] Детали: {e}")
        return []
    except Exception as e:
        print(f"[ERROR] Внутренняя ошибка парсинга ответа: {e}")
        return []

def main():
    print("[INFO] Проверка очереди задач Linear...")
    tasks = fetch_linear_tasks()

    if not tasks:
        print("[INFO] Нет новых задач в очереди.")
        return

    for task in tasks:
        print(f"[{task['identifier']}] {task['title']}")
        # Пример вызова OpenClaw:
        # os.system(f"openclaw execute --branch {task['branchName']} '{task['description']}'")

if __name__ == "__main__":
    main()
```

> **Безопасность:** Токены Linear API имеют широкие права. Храните их только в `.env` на VPS, никогда не хардкодьте в скрипты и установите права на файл (`chmod 600 .env`).

## 3. Терминология: Эпики и Тикеты (Linear)

Linear использует стандартную методологию управления проектами:

## 4. Как работают Issues и Pull Requests в GitHub

GitHub выступает точкой синхронизации между вашим сервером (VPS) и вашим компьютером.

## Локальный цикл автономности (Inner Loop Workflow)

Для реализации этой логики нет необходимости усложнять n8n. Достаточно использовать bash-скрипт на VPS, который выступит локальным микро-оркестратором для конкретной задачи (Issue). Узел `Execute Command` в n8n будет запускать именно этот скрипт.

### Bash-скрипт локальной оркестрации агентов (`agent_loop.sh`)

Скрипт поочередно вызывает кодера и критика, передавая контекст через `stdout` и локальные файлы.

```bash
#!/bin/bash
# Local Agentic Loop: OpenClaw (Coder) -> Antigravity (Reviewer)

# Проверка аргументов
if [ -z "$1" ] || [ -z "$2" ]; then
    echo "[ERROR] Missing arguments. Usage: ./agent_loop.sh <ticket_id> <task_description>"
    exit 1
fi

TICKET_ID="$1"
TASK_DESC="$2"
BRANCH_NAME="feature/$TICKET_ID"
MAX_RETRIES=3
ATTEMPT=0

# Изоляция рабочей среды
git checkout -b "$BRANCH_NAME" || git checkout "$BRANCH_NAME"

while [ $ATTEMPT -lt $MAX_RETRIES ]; do
    echo "[INFO] Attempt $((ATTEMPT+1)): OpenClaw (DeepSeek-V4) is writing code..."
    openclaw run "$TASK_DESC"

    # Сбор незакоммиченных изменений
    DIFF=$(git diff)

    # Базовая обработка: если кодер ничего не сделал
    if [ -z "$DIFF" ]; then
        echo "[ERROR] OpenClaw produced no changes. Aborting."
        exit 1
    fi

    echo "[INFO] Antigravity (Claude 4.6) is reviewing..."
    # Вызов критика с требованием жесткого формата вывода JSON
    REVIEW_RESULT=$(antigravity run "Review this code diff: $DIFF. System Prompt: Analyze for bugs, memory leaks, and logic errors. Output ONLY valid JSON: {\"status\": \"approve\" | \"reject\", \"feedback\": \"details\"}" --model claude-4.6-sonnet)

    # Парсинг ответа агента-критика
    STATUS=$(echo "$REVIEW_RESULT" | jq -r '.status')
    FEEDBACK=$(echo "$REVIEW_RESULT" | jq -r '.feedback')

    if [ "$STATUS" == "approve" ]; then
        echo "[SUCCESS] Code approved by AI Critic. Creating PR..."
        git add .
        git commit -m "feat($TICKET_ID): automated implementation and QA"
        git push origin "$BRANCH_NAME"

        # Создание PR через GitHub CLI
        gh pr create --title "[AUTO] $TICKET_ID" --body "Tested and approved by Antigravity Critic."
        exit 0
    else
        echo "[WARN] AI Critic found issues. Sending back to Coder."
        # Обновляем задачу для кодера, добавляя фидбек критика
        TASK_DESC="Fix the following issues in the current code: $FEEDBACK"
        ATTEMPT=$((ATTEMPT+1))
    fi
done

# Если лимит исчерпан, откатываем изменения и падаем с ошибкой
echo "[ERROR] Reached maximum retries ($MAX_RETRIES). Agents failed to reach consensus."
git reset --hard
exit 1
```

## Интеграция в общую систему

1. **Linear:** Задача переводится в `In Progress`.
2. **n8n:** Ловит вебхук, отправляет команду на VPS: `/opt/scripts/agent_loop.sh "LIN-123" "Напиши роут для API"`.
3. **VPS (Локальный цикл):** - OpenClaw (через DeepSeek V4) пишет код.
   - Antigravity (через Claude 4.6 из вашей подписки) критикует.
   - Если есть ошибки — скрипт закольцовывает их до 3 раз.
4. **Успех:** Скрипт сам делает `git push` и `gh pr create`. Вы видите готовый PR.
5. **Провал (n8n Error Handling):** Если скрипт вернул `exit 1` (циклы исчерпаны, агенты не справились), n8n ловит эту ошибку и меняет статус в Linear на `Needs Human Review`.

## Реализация: Обновленный `agent_loop.sh`

Ниже представлен готовый скрипт с блоком динамического линтинга.

```bash
#!/bin/bash
# Local Agentic Loop: OpenClaw (Coder) -> Linters -> Antigravity (Reviewer)

if [ -z "$1" ] || [ -z "$2" ]; then
    echo "[ERROR] Missing arguments. Usage: ./agent_loop.sh <ticket_id> <task_description>"
    exit 1
fi

TICKET_ID="$1"
TASK_DESC="$2"
BRANCH_NAME="feature/$TICKET_ID"
MAX_RETRIES=4
ATTEMPT=0

# Изоляция рабочей среды
git checkout -b "$BRANCH_NAME" || git checkout "$BRANCH_NAME"

while [ $ATTEMPT -lt $MAX_RETRIES ]; do
    echo "[INFO] Attempt $((ATTEMPT+1)): OpenClaw is writing code..."
    openclaw run "$TASK_DESC"

    # Получаем список измененных или добавленных файлов (исключая удаленные)
    MODIFIED_FILES=$(git diff --name-only --diff-filter=AM)

    if [ -z "$MODIFIED_FILES" ]; then
        echo "[ERROR] OpenClaw produced no changes. Aborting."
        exit 1
    fi

    # ==========================================
    # БЛОК ДИНАМИЧЕСКОГО ЛИНТИНГА
    # ==========================================
    echo "[INFO] Running language-specific linters..."
    LINT_FAILED=false
    > lint_errors.log # Очистка лога

    for FILE in $MODIFIED_FILES; do
        # Пропускаем, если файл не существует
        [ -f "$FILE" ] || continue

        EXT="${FILE##*.}"
        case "$EXT" in
            py)
                echo " - Linting Python: $FILE"
                # Используем ruff как самый быстрый линтер для Python
                ruff check "$FILE" >> lint_errors.log 2>&1 || LINT_FAILED=true
                ;;
            go)
                echo " - Linting Go: $FILE"
                golangci-lint run "$FILE" >> lint_errors.log 2>&1 || LINT_FAILED=true
                ;;
            js|ts)
                echo " - Linting JS/TS: $FILE"
                npx eslint "$FILE" >> lint_errors.log 2>&1 || LINT_FAILED=true
                ;;
            css)
                echo " - Linting CSS: $FILE"
                npx stylelint "$FILE" >> lint_errors.log 2>&1 || LINT_FAILED=true
                ;;
            md)
                echo " - Linting Markdown: $FILE"
                npx markdownlint-cli "$FILE" >> lint_errors.log 2>&1 || LINT_FAILED=true
                ;;
        esac
    done

    # Если линтер нашел ошибки, возвращаем задачу кодеру
    if [ "$LINT_FAILED" = true ]; then
        echo "[WARN] Syntax/Linter errors found. Returning to Coder."
        LINT_OUTPUT=$(cat lint_errors.log | head -n 20) # Берем только первые 20 строк, чтобы не раздувать контекст
        TASK_DESC="Fix the following syntax/linter errors. Do not change the logic, just fix the format:\n$LINT_OUTPUT"
        ATTEMPT=$((ATTEMPT+1))
        continue
    fi
    # ==========================================

    echo "[INFO] Linters passed. Antigravity (Claude 4.6) is reviewing logic..."
    DIFF=$(git diff)
    REVIEW_RESULT=$(antigravity run "Review this code diff: $DIFF. System Prompt: Analyze for architecture, security, and logic errors. Output ONLY valid JSON: {\"status\": \"approve\" | \"reject\", \"feedback\": \"details\"}" --model claude-4.6-sonnet)

    STATUS=$(echo "$REVIEW_RESULT" | jq -r '.status')
    FEEDBACK=$(echo "$REVIEW_RESULT" | jq -r '.feedback')

    if [ "$STATUS" == "approve" ]; then
        echo "[SUCCESS] Code approved by Linters and AI Critic. Creating PR..."
        git add .
        git commit -m "feat($TICKET_ID): automated implementation and QA"
        git push origin "$BRANCH_NAME"

        gh pr create --title "[AUTO] $TICKET_ID" --body "Tested and approved by Linters & Antigravity."
        exit 0
    else
        echo "[WARN] AI Critic found logic issues. Returning to Coder."
        TASK_DESC="Fix the following architectural/logic issues:\n$FEEDBACK"
        ATTEMPT=$((ATTEMPT+1))
    fi
done

echo "[ERROR] Reached maximum retries. Agents failed to reach consensus."
git reset --hard
exit 1
```

## Как правильно настроить взаимодействие раздельных аккаунтов

Чтобы изолированные агенты (Кодер и Критик) могли вместе работать над одними файлами в репозитории, не вызывая ошибок "Permission Denied", необходимо использовать общую группу и механизм **SGID (Set Group ID)**.

> **Важно:** Инструкция ниже предполагает внесение изменений в права доступа. Убедитесь, что применяете команды к правильной директории проекта.

### 1. Создание общей группы

Создайте группу для воркеров и добавьте в нее пользователей-агентов.

```bash
# Создание общей группы
sudo groupadd ai-workers

# Добавление пользователей в группу (замените имена на свои)
sudo usermod -aG ai-workers openclaw_user
sudo usermod -aG ai-workers antigravity_user
# n8n можно не добавлять, если он только отправляет bash-команды на запуск,
# а не редактирует файлы репозитория напрямую.
```

### 2. Настройка рабочей директории (SGID)

Установите права так, чтобы любые новые файлы, созданные OpenClaw, автоматически получали группу `ai-workers`, позволяя Antigravity читать и проверять их.

```bash
# Передача папки проекта во владение группе ai-workers
sudo chown -R :ai-workers /path/to/your/project

# Установка SGID (бит 2) и прав на чтение/запись для группы (775)
sudo chmod -R 2775 /path/to/your/project

# Опционально: применяем права ко всем существующим файлам внутри
find /path/to/your/project -type d -exec chmod 2775 {} \;
find /path/to/your/project -type f -exec chmod 0664 {} \;
```

### 3. Установка маски (umask)

Чтобы агенты создавали файлы с правильными правами по умолчанию, добавьте настройку `umask` в `~/.bashrc` каждого пользователя-агента:

```bash
echo "umask 0002" >> /home/openclaw_user/.bashrc
echo "umask 0002" >> /home/antigravity_user/.bashrc
```

# Архитектура автономной мультиагентной системы разработки

## 1. Концепция и распределение ролей

Разработанная архитектура опирается на событийно-ориентированный подход (Event-Driven). Локальные LLM-модели исключены из процесса оркестрации. Центральным узлом связи выступает n8n, хранилищем состояний — Linear, а точкой контроля (Human-in-the-loop) — GitHub PR.

| Компонент / Инструмент     | Выполняемая роль                                                        | Модель ИИ                                 |
| :------------------------- | :---------------------------------------------------------------------- | :---------------------------------------- |
| **Linear**                 | Управление состояниями (State Machine). Источник задач (Epics, Issues). | -                                         |
| **n8n**                    | Event Bus и Планировщик. Маршрутизация вебхуков, декомпозиция задач.    | Google Gemini 1.5 Pro (via AI Studio API) |
| **OpenClaw (VPS)**         | Агент-кодер. Выполнение bash-команд, написание кода.                    | DeepSeek-V4-Pro (API)                     |
| **Antigravity (VPS)**      | Агент-критик. Ревью кода, поиск логических уязвимостей.                 | Claude 4.6 (via Google One AI Credits)    |
| **Zoo Code + Qdrant (PC)** | Среда контроля человека. RAG-поиск, ревью PR, слияние веток.            | DeepSeek-V4-Pro / Flash                   |
| **GitHub**                 | Шина данных. Изоляция рабочих веток, механизм Pull Requests.            | -                                         |

## 2. Глобальный конвейер (CI/CD Pipeline)

1. **Инициализация:** Человек создает `Epic` или `Issue` в Linear.
2. **Декомпозиция:** n8n перехватывает Webhook от Linear, обращается к Google AI Studio API для декомпозиции глобальной задачи на атомарные шаги.
3. **Запуск:** n8n через узел `Execute Command` инициирует локальный цикл (Inner Loop) на VPS для конкретного тикета.
4. **Завершение:** По итогу локального цикла создается Pull Request в GitHub, статус в Linear меняется на `In Review`.
5. **Контроль:** Человек проверяет PR через локальный ПК (Zoo Code) и выполняет Merge.

## 3. Локальный цикл автономности (Inner Loop на VPS)

Процесс "написание-проверка-исправление" изолирован внутри VPS с помощью bash-скрипта-оркестратора, чтобы минимизировать нагрузку на API GitHub и исключить "мусорные" коммиты.

**Алгоритм локального цикла:**

1. OpenClaw создает изолированную git-ветку и генерирует код по задаче.
2. Скрипт анализирует измененные файлы (через `git diff --name-only`).
3. Запускаются статические линтеры (Ruff, golangci-lint, eslint) для соответствующих расширений файлов.
   - При наличии синтаксических ошибок задача возвращается OpenClaw.
4. При успешном прохождении линтеров вызывается Antigravity (Claude 4.6).
   - Критик получает жесткий промпт на проверку уязвимостей и утечек памяти (вывод строго в JSON).
   - При наличии логических ошибок цикл возвращается к OpenClaw.
5. При достижении консенсуса скрипт выполняет `git push` и `gh pr create`.

## 4. Безопасность и управление доступом на сервере

Реализован принцип наименьших привилегий (Principle of Least Privilege). Объединение агентов под один аккаунт root или единого пользователя исключено.

- **Раздельные аккаунты:** `openclaw_user` и `antigravity_user`.
- **Общие бинарники (Линтеры):** Устанавливаются глобально в `/usr/local/bin/` с правами на исполнение (`chmod 755`), выполняются от имени непривилегированных пользователей-воркеров.
- **Доступ к файлам проекта (SGID):** \* Создана общая системная группа `ai-workers`.
  - Директория проекта настроена с флагом SGID (`chmod 2775`).
  - Установлена `umask 0002` для агентов, гарантирующая права на чтение и запись для всех членов группы.

## 5. Аналитический вывод

Спроектированная архитектура решает ключевые проблемы мультиагентных систем: потерю контекста, галлюцинации моделей и конфликты доступа. Использование n8n и Linear снимает с нейросетей нетипичные для них задачи жесткой логики и поллинга. Разделение ролей на Кодера (DeepSeek) и Критика (Claude 4.6), с промежуточным звеном в виде детерминированных CLI-линтеров, формирует самокорректирующийся цикл с высоким качеством выходного кода и минимальными затратами токенов. Система легко масштабируется и оставляет за человеком исключительное право финального принятия решений (Merge PR), защищая production-среду от непредвиденных действий ИИ.
